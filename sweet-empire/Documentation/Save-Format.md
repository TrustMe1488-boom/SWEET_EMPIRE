# Сохранения 1.0.0-dev.1

Рабочий путь: `user://progress/save.dat`. Для обычного Windows-запуска user://
определяется Godot в пользовательском app_userdata; это не res:// и не PCK.
Тестовый runner перенаправляет только окружение дочернего процесса в `.local/`.

Контейнер: magic `SWEET001` (8 байт), длина payload uint32, SHA-256 (32 байта),
payload Godot binary Variant. Общий размер ограничен 16 MiB. Декодирование объектов
отключено стандартным bytes_to_var; Transform3D, Vector3, Color и int64 RNG
сохраняются без потери точности JSON. SHA проверяет случайное повреждение, не
аутентичность данных.

Запись: save.pending → flush/close → повторное чтение и сравнение → копия последнего
валидного save.dat в save.previous с проверкой → замена save.dat через rename.
При незавершённой записи основной файл или previous остаётся доступным. При чтении
повреждённого/обрезанного primary применяется предыдущая целая копия.
В production проверяется также схема profile/world/settings. Семантически
некорректный primary не заменяет валидную previous; перед его перезаписью сохраняется
отдельный `save.corrupt.<ticks>` для диагностики.

Payload.version=1 содержит profile (кошелёк, cosmetic debit ledger, владение и
выбранные стили), game (мир и progression), и пустое поле settings для совместимости.
Настройки сохраняются отдельно в `user://settings.cfg`; прежние настройки из payload
переносятся при первом запуске, если отдельного файла ещё нет. Game включает зоны, станции/поваров, товары/кассу/поднос, очередь,
клиентов и их состояние, кассира, трафик, аналитику, RNG, Мию/камеру, Rush и checkpoint.
Progression включает обучение, главы, задания, достижения, одноразовые награды,
repeatable-квесты и дедупликацию событий.
Магазин до нажатия «Продолжить» обновляет также ещё не созданный мир: покупка
согласует pending wallet и Rush checkpoint, не расходуя временные кристаллы.

Автозагрузка профиля происходит в GameSession. Мир создаётся при выборе продолжения,
после проверки схемы; игровые данные не заменяются через profile-load живой пекарни.
Кошелёк profile должен совпадать с кошельком кампании. Конструирование визуальных
станций выполняется при suspended progression, затем восстанавливается ledger
событий, чтобы загрузка не начисляла награды за повторное создание узлов.

Моменты записи: 60 секунд, возврат в меню, изменение косметики, штатный выход и
закрытие окна. Камера, PID worker и согласие на запуск камеры не сохраняются:
каждый запуск начинается с отключённой камеры. Калибровку нужно повторить вручную.

Проверки: stabilization_tests (повреждение и previous, int64/Vector3 roundtrip,
атомарность отказа загрузки), persistence_restart_tests (расширенный мир между
процессами), test_boot_persistence.py (реальные автозагрузка/продолжение и покупка
косметики между тремя запусками приложения). Общий строгий результат Godot пока
FAIL из-за ошибки root certificate store, даже при нуле ошибок этих assertions.

Не подтверждены: устойчивость к реальному отключению питания, длительная сессия
до лимита файла, полная матрица Rush/Endless и повреждённые файлы с намеренно
пересчитанной SHA. Несовместимый по схеме мир отклоняется; исходный файл сохраняется.

## Новая игра

Меню запрашивает подтверждение, если есть живая сессия или любой файл основного
или предыдущего сохранения, включая повреждённый. После подтверждения перед сбросом
создаются отдельные `save.before-new-*.dat` для существующих файлов; настройки не
сбрасываются. При отмене ничего не меняется. Текущий экземпляр BakeryGame и профиль
заменяются начальными объектами, а начальное состояние сохраняется после готовности
новой сцены. При ошибке создания копии замена не начинается.
